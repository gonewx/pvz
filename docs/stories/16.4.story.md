# Story 16.4: 渲染偏移量统一化

## Status
Done

## Story
**As a** 游戏开发者,
**I want** 将分散在多处的渲染偏移量计算逻辑统一到坐标转换工具库中,
**so that** 消除硬编码的特殊实体偏移补丁、降低维护成本、提高代码一致性，并为未来新增实体类型提供标准化的渲染定位基础。

## Dev Notes

### 问题背景

**当前问题**：
[Source: Sprint Change Proposal SCP-2025-12-001, Story 16.4 PO Validation 2025-12-12]

1. **渲染偏移量机制分散**：
   - `CenterOffset`：BoundingBox 中心偏移，在动画初始化时计算
   - `ShadowOffset`：阴影位置微调，在 `shadow_config.go` 中定义
   - `PolevaulterZombieShadowOffsetY`：特殊实体补丁，硬编码在 `unit_config.go`
   - 这些机制独立运作，没有统一的协调逻辑

2. **⚠️ 重要发现：补丁存在但未生效**：
   - `PolevaulterZombieShadowOffsetY = 15.0` 存在于 `unit_config.go:95`
   - 该值被存储到 `ShadowComponent.OffsetY`（见 `zombie_factory.go:633`）
   - **但是 `render_system.go` 从未读取 `ShadowComponent`！**
   - `drawZombieShadowsWithClipping()` 对所有僵尸统一使用 `config.ZombieShadowOffsetY`
   - **结论：撑杆僵尸的特殊阴影偏移从未被应用**

3. **`ShadowComponent` 设计但未使用**：
   - 组件定义存在于 `pkg/components/shadow_component.go`
   - 工厂函数为每个实体创建 `ShadowComponent`
   - 但渲染系统完全忽略此组件，直接使用全局配置
   - 这是需要清理的技术债务

4. **装备轨道识别基于命名规则**：
   - `isEquipmentTrack()` 函数使用关键词匹配（bucket, cone, flag, pole 等）
   - 新增装备类型需要更新关键词列表
   - 容易遗漏或出错

---

### 解决方案

**核心思路**：阴影位置应该基于实体的脚底位置，而不是 `pos.Y + 偏移量`

**关键洞察**：
- `CenterOffsetY` 已经使用 `maxY`（脚底位置）作为锚点
- 因此 `pos.Y - CenterOffsetY` 就是实体的脚底位置
- 阴影应该绘制在脚底位置下方，而不是基于 `pos.Y` 加上各种补丁

**实现方案**：

1. **添加 `GetFootPosition()` 函数**：
   ```go
   // 获取实体脚底位置（世界坐标）
   // 脚底位置 = pos.Y - 0 = pos.Y（因为 CenterOffsetY = maxY，渲染时已对齐）
   // 实际上脚底 = pos.Y（因为 screenY = pos.Y - CenterOffsetY，而 CenterOffsetY = maxY）
   func GetFootPosition(em, entityID, pos) (footX, footY, err)
   ```

2. **添加 `GetShadowScreenPosition()` 函数**：
   ```go
   // 统一计算阴影屏幕坐标
   // screenX = pos.X - cameraX + offsetX - shadowWidth/2
   // screenY = pos.Y + offsetY - shadowHeight/2
   func GetShadowScreenPosition(em, entityID, pos, cameraX, shadowW, shadowH, offsetX, offsetY) (screenX, screenY, err)
   ```

3. **重构阴影渲染系统**：
   - 使用统一的 API 计算阴影位置
   - 删除特殊实体补丁

### 坐标计算分析

**CenterOffset 计算逻辑**（来自 `reanim_helpers.go:206-355`）：

```go
// CenterOffsetX: 使用几何中心（水平居中）
comp.CenterOffsetX = (minX + maxX) / 2

// CenterOffsetY: 使用 maxY（脚底位置）作为锚点
// 这是最优雅的解决方案：
// - 脚底位置是最稳定的，不受任何装备影响
// - 无需判断哪些是装备轨道，无需硬编码任何数值
// - 所有实体的脚底自然对齐
comp.CenterOffsetY = maxY
```

**渲染公式**：
```go
// 渲染系统（render_reanim.go）
screenY = pos.Y - CenterOffsetY
// 由于 CenterOffsetY = maxY，渲染后实体的脚底对齐到 pos.Y
```

**阴影公式（当前实现）**：
```go
// render_system.go:drawZombieShadows
footY := pos.Y + shadowOffsetY  // 这里 pos.Y 已经是脚底位置！
screenY := footY - shadowImgHeight/2
```

**问题分析**：
- 阴影公式正确假设 `pos.Y` 是脚底位置
- ~~但对于装备僵尸，由于 `isEquipmentTrack()` 排除了装备轨道~~
- ~~导致 `CenterOffsetY` 只计算身体的 maxY，不包含装备~~
- ⚠️ **PO 验证结果**：`render_system.go` 从不读取 `ShadowComponent.OffsetY`
- 所有僵尸（包括撑杆僵尸）都使用相同的 `config.ZombieShadowOffsetY` 全局配置
- `PolevaulterZombieShadowOffsetY` 补丁存在但从未被应用

**结论**：
1. ~~当前的补丁 `PolevaulterZombieShadowOffsetY` 可能是不必要的，需要验证。~~
2. **已验证**：补丁从未生效，可以安全删除
3. 需要先运行游戏确认撑杆僵尸阴影位置是否正确（Task 0）

#### Task 7 手工验证修复记录 (2025-12-12)

**发现的问题及修复**：

1. **撑杆僵尸阴影不显示**
   - 原因：`drawZombieShadowsWithClipping()` 中的僵尸类型检查遗漏了 `BehaviorZombiePolevaulter`
   - 修复：在 `render_system.go:1384` 添加撑杆僵尸类型检查

2. **撑杆僵尸阴影偏左**
   - 原因：`calculateCenterOffset()` 计算 `CenterOffsetX` 时包含了撑杆装备轨道
   - 修复：在 `reanim_helpers.go` 中使用 `isEquipmentTrack()` 函数排除装备轨道的 X 范围计算
   - 结果：`CenterOffsetX` 只基于僵尸身体计算，装备不影响水平居中

3. **阴影位置与实体不同步**
   - 原因：阴影计算公式过于复杂，没有直接跟随实体 `pos.Y`
   - 修复：简化阴影计算公式为 `footY = pos.Y + shadowOffsetY`
   - 结果：阴影直接跟随实体位置，调整 `PlantOffsetY` 或 `ZombieVerticalOffset` 时阴影自动同步

**最终阴影计算公式**：
```go
// 植物阴影
footY := pos.Y + config.PlantShadowOffsetY

// 僵尸阴影
footY := pos.Y + config.ZombieShadowOffsetY
```
