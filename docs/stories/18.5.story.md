# Story 18.5: 植物序列化扩展性重构

## Status

Done

## Story

**As a** 开发者,
**I want** 重构植物序列化系统使其具备扩展性,
**so that** 新增植物类型时无需修改多处代码，且现有植物类型（土豆地雷、樱桃炸弹、寒冰射手等）能正确保存和恢复。

## Acceptance Criteria

1. **使用 PlantTagComponent 识别植物**
   - 创建 `PlantTagComponent` 标签组件
   - 所有植物工厂函数添加 `PlantTagComponent`
   - 移除 `collectPlantData` 中基于 `PlantComponent` 的硬编码查询
   - 使用 `PlantTagComponent` 查询所有植物实体
   - 新增植物类型自动被识别（只需工厂函数添加 PlantTagComponent）

2. **使用 PlantType 作为类型标识**
   - 直接使用 `PlantComponent.PlantType.String()` 作为 `PlantData.PlantType`
   - 移除 `stringToPlantType()` 类型转换函数
   - 恢复时根据植物类型字符串选择正确的工厂函数

3. **工厂函数注册表**
   - 创建植物工厂函数注册表 `plantFactories map[string]PlantFactory`
   - 定义统一的 `PlantFactory` 函数签名（使用 `PlantFactoryDeps` 结构体封装依赖）
   - 注册现有植物类型的工厂函数
   - 恢复时通过植物类型字符串查找对应的工厂函数
   - 新增植物类型只需在注册表添加一行

4. **土豆地雷状态的保存和恢复**
   - 收集 `PlantComponent` 中的土豆地雷状态（`PotatoMinePhase`, `ArmingTimer`）
   - 恢复时正确设置土豆地雷的武装阶段和计时器
   - 架构设计支持未来其他植物特有状态（如樱桃炸弹的引信状态）

5. **移除硬编码的 switch-case**
   - 删除 `restorePlants` 中的 switch-case 植物类型判断
   - 统一使用工厂注册表创建植物实体

6. **单元测试**
   - 添加工厂注册表测试（已知类型/未知类型/默认工厂）
   - 添加土豆地雷序列化/反序列化测试（各阶段状态）
   - 验证各植物类型的序列化/反序列化正确性

## Dev Notes

### 问题背景

参考 Story 18.4 的僵尸序列化扩展性重构，植物序列化存在类似的硬编码问题：

1. **collectPlantData() 使用 PlantComponent 查询**：`pkg/game/battle_serializer.go:174-227`
   - 目前使用 `GetEntitiesWith2[*PlantComponent, *PositionComponent]`
   - 没有使用标签组件识别植物
   - **未收集土豆地雷状态**（PotatoMinePhase, ArmingTimer 字段未使用）

2. **restorePlants() 硬编码 switch-case**：`pkg/scenes/game_scene_init.go:792-907`
   - 使用 `stringToPlantType()` 转换类型
   - 每个植物类型需要单独的 case 分支
   - 新增植物类型需要修改此函数
   - **未恢复土豆地雷状态**

### 统一工厂签名设计

使用依赖结构体封装所有可能的依赖，不需要的工厂函数可以忽略：

```go
// PlantFactoryDeps 植物工厂依赖
type PlantFactoryDeps struct {
    EntityManager   *ecs.EntityManager
    ResourceLoader  ResourceLoader
    GameState       *game.GameState
    ReanimSystem    ReanimSystemInterface  // 可选，部分植物不需要
}

// PlantFactory 统一的植物工厂函数签名
type PlantFactory func(deps PlantFactoryDeps, col, row int) (ecs.EntityID, error)

// 植物工厂注册表
var plantFactories = map[string]PlantFactory{
    "sunflower":   newSunflowerFactory,
    "peashooter":  newPeashooterFactory,
    "wallnut":     newWallnutFactory,
    "cherrybomb":  newCherryBombFactory,
    "potatomine":  newPotatoMineFactory,
    "snowpea":     newSnowPeaFactory,
}

// 适配器函数示例
func newSunflowerFactory(deps PlantFactoryDeps, col, row int) (ecs.EntityID, error) {
    return NewPlantEntity(deps.EntityManager, deps.ResourceLoader, deps.GameState,
        deps.ReanimSystem, components.PlantSunflower, col, row)
}

func newPotatoMineFactory(deps PlantFactoryDeps, col, row int) (ecs.EntityID, error) {
    return NewPotatoMineEntity(deps.EntityManager, deps.ResourceLoader, deps.GameState, col, row)
}
```

### 架构原则

[Source: architecture/coding-standards.md#零耦合原则]
- **开放-封闭原则**：新增植物类型无需修改序列化核心逻辑
- **单一职责**：工厂函数负责创建，序列化器负责收集/恢复
- **ECS 模式**：使用组件（PlantTagComponent）而非类型判断
- **数据-行为分离**：组件仅存储数据，系统处理逻辑
